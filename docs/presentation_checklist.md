# PPDA — Backend Submission & Presentation Checklist

This file is the "before you submit / before you present" checklist for the
**Privacy-Preserving Digital Assistant (PPDA) backend**.

---

## 1. What was already fixed on this branch (no action needed)

- **ONNX model was broken in the repo.** The committed `deployed_models/intent_model.onnx`
  referenced an external sidecar (`intent_model.onnx.data`) that was *not* committed
  (and was git-ignored), so `onnx_classifier.available` was `False` and the app fell
  back to TF-IDF. It is now exported **self-contained** with `external_data=False`:
  `deployed_models/intent_model.onnx` (~269 KB, no sidecar file).
- **`python scripts/train_assistant_intent.py` now works from the repo root.** It was
  failing with `ModuleNotFoundError: No module named 'app'` because the script could
  not find the repo root on `sys.path`.
- **`fl/deploy/export_onnx.py` now writes the model path the app actually loads**
  (`deployed_models/intent_model.onnx`) instead of `intent_fp32.onnx`, so exporting a
  federated round now updates the live ONNX artifact used by `/api/v1/*`.
- **Generated bytecode no longer tracked in Git.** Removed 77 tracked
  `__pycache__/*.pyc` files from the repo.
- **Virtualenv consistency + gitignore.** README local setup now uses `.venv`,
  and `venv/` is git-ignored so a local env won't be accidentally submitted.
- **`task.md` checkboxes are marked complete** (`[x]`) to match the implemented code.

## 3. Local live demo (no Docker / no PostgreSQL)

The cleanest demo path for a presentation is SQLite + uvicorn.

```bash
cp .env.example .env
# In .env set:
#   DATABASE_URL=sqlite:///./ppda.db

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt onnxscript

alembic upgrade head
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

- Swagger UI: `http://localhost:8000/docs`
- Health: `http://localhost:8000/health`
- FL coordinator state: `GET /api/v1/fl/round/status`

Show this sequence to prove the privacy/security claims:

1. **Register** `POST /api/v1/users`
2. **Login** `POST /api/v1/login` → get `access_token`
3. **Call authenticated endpoints with that bearer token** — e.g.
   `GET /api/v1/users/me`, `POST /api/v1/consent`, calendar/reminder CRUD.
4. **Prove IDOR immunity**: request `/api/v1/users/{another_id}` → `404` (not `403`),
   so the API does not reveal whether other users exist.
5. **Prove encryption at rest**: look at the raw row in the DB (`calendar_events`,
   `reminders`, `messages`) — titles/texts are AES-256-GCM ciphertext, not plaintext.
6. **Prove audit immutability**: `GET /api/v1/audit/verify`; try to `UPDATE` or
   `DELETE` an `audit_logs` row directly in SQL → the DB trigger rejects it.
7. **Prove on-device intent**: `POST /api/v1/assistant/command`
   (`{"text": "remind me to buy milk tomorrow"}`). ONNX Runtime is active
   (`model_inference.active_backend() == "onnx"`) and `external_calls: 0`.
8. **Privacy posture endpoint**: `GET /api/v1/privacy/posture` shows exactly what is
   implemented vs. architecture-only — great for answering questions.
9. **Encryption demo endpoint**: `POST /api/v1/privacy/encrypt-demo`
   (`{"plaintext": "meeting with client at 3pm"}`) shows the AES-256-GCM ciphertext and
   decryption round-trip live.

## 4. Federated Learning demo (the centerpiece)

Reproducible one-shot (downloads SNIPS + runs real client processes):

```bash
./scripts/run_fl_demo.sh
```

Or manually:

```bash
.venv/bin/python -m fl.data.prepare --clients 6 --alpha 0.5
.venv/bin/python -m uvicorn fl.server.app:app --host 0.0.0.0 --port 8000 &
for i in {0..5}; do .venv/bin/python -m fl.client.run --client-id $i --server-url http://localhost:8000 & done
.venv/bin/python -m fl.experiments.run_sweep --rounds 20 --local-epochs 1 --clip-norm 20 --clients-per-round 3 --epsilons none,10,5,1 --out fl_results.json
.venv/bin/python -m fl.deploy.export_onnx
.venv/bin/python -m fl.deploy.benchmark
```

Artifacts to show:
- `results/accuracy_vs_epsilon.png`
- `results/metrics_summary.csv`
- `docs/federated_learning.md`
- `deployed_models/intent_model.onnx` + `fl/deploy/benchmark` output (`benchmark.json`)

**Key story to tell:** the server only ever receives masked `uint32` vectors; it has no
code path to an individual client update. The privacy/utility trade-off is *measured* —
accuracy is monotone in ε (∞ → 10 → 5 → 1), and at small ε the model is close to chance.

## 5. What to say honestly (reviewers love this)

These are *real* limits, and saying them out loud is stronger than overclaiming:

- **Secure aggregation** is Bonawitz et al. CCS'17 (X25519 ECDH, ChaCha20 PRG,
  Shamir shreds). It protects against an **honest-but-curious server**, not a
  malicious server (which could sybil) or malicious clients (no poison robustness).
- **Crypto is hand-rolled from-scratch research-grade**; it has not had a third-party
  security audit. Do not claim it is production-hardened.
- **DP is client-level and real**, but with only 6 clients there is little
  subsampling amplification; at ε = 1 the model is near chance. The honest claim is
  "the trade-off is real and measured", not "DP is free".
- **INT8 compression is 1.02×**, not ~4×, because most parameters live in an
  `EmbeddingBag` that dynamic quantization leaves in fp32. The real on-device fact is
  "the whole model is a quarter of a megabyte".
- **HE / SGX / TrustZone / PIR are architecture notes only** — explicitly not built.
